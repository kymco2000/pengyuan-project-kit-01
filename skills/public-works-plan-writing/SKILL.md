# 公共工程計畫書撰寫

## 核心原則

先確認「本案要提送什麼」與「每項內容依據何在」，才開始撰寫。契約、招標文件、現行圖說、施工規範、核定監造計畫、機關書面指示及指定範本優先；案例僅可用於章節、流程與查核邏輯，不可移植技術數值、頻率、人名、廠商資料或機關特殊管制。

## 適用流程

| 情境 | 必要產出 |
|---|---|
| 尚未確認提送要求 | 送審依據矩陣、缺件清單；不假定「三大計畫書」一定適用。 |
| 已有正式依據、尚未起草 | 計畫書骨架與章節—來源對照表。 |
| 已有草稿或核定版 | 差異審查表，逐條指出缺項、錯引、待確認及應回扣的來源。 |

### 1. 先建送審依據矩陣

逐項列出：計畫書名稱、提送主體（施工廠商／監造單位）、契約或機關依據、提送期限、指定格式、必備附件、核定狀態與缺件。只有正式來源明列時，才判定計畫書須獨立成冊；職安、環保、交維、緊急應變等可能是整體施工計畫章節，也可能須獨立提送。

### 2. 建立章節—證據對照

每章先列「待填項目、依據檔名、條文／頁碼／圖號、版次、責任人、狀態」。工程名稱、範圍、工期、數量、施工方法、材料規格、檢驗頻率、停留點、職掌與聯絡方式均須可回扣正式來源。欠缺依據時標示 `待確認`，不得以案例補值。

### 3. 依計畫類型編寫

- **整體施工計畫**：工程概要、前置作業、施工組織、資源與進度、工區與假設工程、分項施工方法、測量、職安、環保、交維、緊急應變、驗收移交。章節是否保留取決於本案要求。
- **整體品質計畫**：範圍、權責、施工要領、品質標準、材料／施工檢驗、自主檢查、不合格品、矯正預防、品質稽核、文件紀錄；對每一工項建立「標準 → 檢查方法與時機 → 責任 → 紀錄 → 不符合處置」鏈。
- **監造計畫**：僅於監造單位受託編製時使用；重點為審查、抽驗、施工抽查、稽核與紀錄管理，不能與施工廠商的自主品管職責混寫。
- **職安、環保、交維或防災計畫**：先由依據矩陣決定其為獨立冊或整體施工計畫章節，再依風險、工項與機關要求撰寫。

### 4. 案例與知識庫使用界線

案例可協助找出常見的章節、流程、附件與審查問題。中科院／營區／醫療院所等案例的保密、出入、人員、設施、試驗或作業規定，只有本案正式來源明示時才可寫入。需要查筆記庫時，優先閱讀：

- `01_工作區/04_工作技能與範本/公共工程與監造/公共工程品管與監造範本庫/00_公共工程品管與監造體系解構指南.md`
- `01_工作區/04_工作技能與範本/公共工程與監造/公共工程品管與監造範本庫/01_核定計畫書架構範本.md`
- 與本案同名專案資料夾；其筆記只作索引，正式原始檔仍是唯一依據。

## 交付前檢核

- 計畫書名稱、冊別、提送期限及提送主體均已具可追溯依據。
- 每一技術規格、數量、頻率、期限、責任人及管制點可回查來源；否則標示 `待確認`。
- 範本、表單、編碼、簽章欄與版次使用本案指定版本。
- Word 文件以樣式、欄位、圖表標號及交叉參照管理；輸出前更新欄位並檢查版面。

## 常見錯誤

| 錯誤 | 正確處理 |
|---|---|
| 一律要求「三大計畫書」 | 以送審依據矩陣判定每本是否獨立提送。 |
| 複製其他案的檢驗頻率、規格或停留點 | 僅取其流程，逐項回扣本案契約、圖說與核定內容。 |
| 把監造抽查與廠商品質自主檢查混成一張表 | 依提送主體與責任分開設計、分開留存。 |
| 沒有正式資料就填入看似合理的工程內容 | 列資料缺口與 `待確認`，停止填寫該事實。 |
