# Public Works Supervision Local Management

Manage the local project record as the auditable source of truth. Use PMIS only as an optional reporting destination.

## Source Gate

Before creating folders or drafting a project document, inspect the available contract, tender documents, current drawings, approved plans, agency rules, and retained office templates. Record title, revision/status, date, owner, and location.

Mark a matter `待確認` when its governing source is missing. Do not infer scope, quantities, specifications, dates, costs, acceptance criteria, or authority. Do not create a new form if an approved project or office form exists.

## New Project Setup

After the source gate, create only the management areas required by the project: approvals; contract baseline; drawings/specifications; plans/reviews; quality/inspections; estimates; changes; RFIs; correspondence; meetings; BIM; safety/environment; inspections; completion, acceptance, and warranty.

Use the agency naming rule. If none exists, propose `YYYYMMDD-DocumentNo-Subject-Discipline-Revision-Status` before bulk creation.

Maintain control registers for recurring matters. Link each record to source files, document number, owner, due date, status, and close-out evidence.

## Operating Controls

| Trigger | Required control |
|---|---|
| Daily activity or received document | File the source, identify basis, assign owner/due date, update register. |
| Weekly meeting | Carry unresolved items; record decision, owner, deadline, evidence, and control/close status. |
| Estimate/payment | Verify contract item, completed quantity, inspection evidence, approved price, cumulative quantity, deductions, and change status. |
| RFI | Cite source, fact, impact, requested decision, and written reply. |
| Change or extension | Preserve baseline; quantify scope/price/time; obtain approvals and written contract change; update affected records. |
| Defect, safety issue, audit, incident | Preserve evidence, issue the applicable notice, verify correction, and close with documented acceptance. |

## Contract, Change, and Estimate

Treat an RFI reply as clarification unless it changes scope, quantity, price, duration, payment, specification, or another performance condition. Do not treat oral directions, chat messages, or unapproved changes as contract changes.

Do not include new or changed items in ordinary estimate payment without contract basis and required written authorization. For authorised advance work, preserve the written direction and agreed payment/change deadline.

Maintain this chain: baseline → RFI/meeting/field evidence → approved decision → written contract change → inspection/payment → as-built/acceptance.

## Exact Document Format

Copy the designated approved source template and change only project-specific content. Preserve page setup, fonts, spacing, headers/footers, table geometry, merged cells, numbered fields, signatures, and status labels. Do not rebuild a similar form.

Select one controlling template by purpose, status, and revision; reject draft, archive, duplicate, or obsolete versions unless explicitly selected.

## Delivery Check

Confirm every folder, register, document, or recommendation has a governing source, correct status/version, required evidence, owner, deadline, and storage location. State unresolved dependencies.
